Comment ça marche

1

Branchez GitHub

Installez l'application GitHub sur votre organisation et choisissez les dépôts de vos logiciels.

2

Invitez l'équipe

Chacun entre avec son e-mail de travail et un lien magique. Pas de compte GitHub, pas de mot de passe.

3

Suivez comme un colis

Reçue, planifiée, en réalisation, en test, disponible. Chaque étape vient de GitHub, sans saisie en double.

Pour l'équipe

  • Une demande en deux minutes, guidée, depuis l'ordinateur ou le téléphone.
  • Une capture d'écran annotée, collée ou prise sur place.
  • « C'est aussi mon cas » au lieu d'un doublon.
  • Les nouveautés expliquées avec des mots simples.

Pour les développeurs

  • Rien ne change : issues, sous-issues, PR, déploiements.
  • Des issues complètes, avec critères d'acceptation et vérification.
  • Prêtes à être confiées à un agent de code.
  • Le triage de tous les dépôts au même endroit.

Serveur MCP intégré

Une phrase à Claude, une fonctionnalité prête.

Hublot embarque un serveur MCP. Depuis Claude, demandez une fonctionnalité : elle arrive avec toutes ses issues, remplies avec les mêmes champs que la création guidée, et vérifiées avant d'entrer dans GitHub.

  • Claude agit avec vos droits, ni plus ni moins.
  • Il manque une information ? Hublot le dit, Claude vous la demande.
  • En brouillon par défaut : rien n'entre dans GitHub sans votre accord.
  • Chaque action est tracée « via Claude ».

terminal

claude mcp add --transport http hublot [VOTRE INSTANCE]/mcp

Chez vous, en une commande

Une image Docker, une base Postgres, un stockage compatible S3 pour les captures. Vos données ne quittent pas votre serveur.

L'assistant d'installation crée l'application GitHub pour vous.

terminal

git clone [URL DU DÉPÔT]
cd hublot
cp .env.example .env
docker compose up -d
